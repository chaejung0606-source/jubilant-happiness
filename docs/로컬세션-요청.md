# 로컬 세션 요청문 (복붙용)

웹앱(이 리포)은 클라우드 세션이, 데스크톱 Excel·시트 쓰기는 로컬 세션이 맡는다.
아래 블록을 **통째로 복사해 로컬 세션에 붙여넣으면** 된다. 끝나면 결과 파일을 이 대화(클라우드)에 업로드.

> 갱신: 2026-11-17 · 담당 = 자산 재이관(Path 1) + RFID 교정

---

## ▶ 지금 요청 (복붙 블록) — Path 1: 새 스키마로 재이관

왜: 현재 배포된 Code.gs가 구버전(assets 11열)이라 **규격·태그번호·수정기록 열이 비어 있음**.
새 Code.gs(17열 + 대여 16열 + accounts + id 텍스트고정 + meta + 대량반입)로 올리고,
assets를 새 스키마로 다시 채운다. (CSV는 RFID 교정분까지 반영해 새로 받는 중)

### 1) Apps Script 재배포 (브라우저, 1회)
- 리포 `apps-script/Code.gs` 전체 복사 → 그 시트의 확장프로그램>Apps Script에 붙여넣기(덮어쓰기)
- 배포 → 배포 관리 → 편집 → 새 버전 → 배포 (웹앱 URL 그대로)

### 2) assets 탭 비우기 (브라우저)
- 구글시트에서 **assets 탭의 모든 행을 삭제**(헤더 포함) 또는 탭 자체 삭제.
  → 다음 반입 때 17열 헤더가 자동 재생성되고 id가 텍스트로 저장됨.

### 3) 재이관 (로컬, 빠른 대량반입)
```
git pull
npm run apply:daesa -- "대장전체_YYYYMMDD.csv"                # 미리보기: 대상 915건
npm run apply:daesa -- "대장전체_YYYYMMDD.csv" --bulk --commit # 대량 반입(수 초)
```
- 끝나면 /assets 에서 915건 + 규격·태그번호 채워졌는지 확인.
- ※ 이전 'apply:daesa 기본 136건'은 실행 금지(키 달라 중복).

### 4) RFID 교정 17건 (연번 769~785)
- 대장엔 전부 …00000036 오기 / 학교는 …040~056. 새 대장 CSV에 교정 반영하면
  3)에서 자동 포함. 따로 보낼 땐 (관리번호, RFID) CSV → `--update` 로 반영.
```

## (이전) 이관 자료 요청 — 완료

```
[COSS 자산관리 — 로컬 세션 작업 요청]

맥락: 이제 Excel이 아니라 웹앱(구글시트 DB)에서 자산을 관리한다.
      기존 대장 데이터와 채번 조회표를 웹앱으로 옮기려 한다.
      원본 대장은 수정하지 말고 '사본'에서만 작업하고, 결과는 CSV(UTF-8)로 내보내 줘.

대상 파일: C:\Users\User\Desktop\★사업단 운영\2. 자산 물품 관리\자산태그\자산관리대장(사본)
          (사본 예: 자산관리대장_261022.xlsm)

── 작업 1. 전체 대장 CSV 내보내기 (웹앱 이관용) ──
- 연번 1 ~ 915 전체 행을, 아래 17개 열 순서/머리글 그대로 CSV(UTF-8)로 저장.
- 관리번호는 O열 수식 결과값(문자열)을 넣는다. #N/A·빈 행은 제외.
- 열: 연번, 관리번호, 자산번호, RFID, 품명, 규격, 대분류, 중분류, 분류코드,
      취득일, 취득단가, 번호, 장소, 호실, 건축물코드, 관리기관, 사용처
  · 자산번호 = 학교 Z번호,  취득일 = YYYY-MM-DD,  취득단가 = 숫자만
- 파일명: 대장전체_YYYYMMDD.csv

── 작업 2. 건축물코드 표 전체 ──
- '건축물 코드' 시트의 (건물명 → B코드) 전체를 CSV로.
- 열: 건물명, 건축물코드
- 파일명: 건축물코드표.csv

── 작업 3. 중분류 → 분류코드 표 ──
- 품목 분류 조회표에서 (중분류명 → 분류코드) 전체를 CSV로.
  (가능하면 대분류도 같이)
- 열: 대분류, 중분류, 분류코드
- 파일명: 분류코드표.csv

완료 후 3개 CSV를 클라우드 세션 대화에 업로드. 추측 금지 — 애매하면 비워 두고 알려줘.
```
